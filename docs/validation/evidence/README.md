# Partner Pilot evidence

Machine-produced, redacted evidence for the Partner Pilot acceptance gates. Every
file here is regenerated by a command; none of it is hand-written, and none of it
contains client data — the Archicad side runs against the representative in-repo
model (`pilot/partner/replay_model.json`), the product side against an in-memory
database.

| File | Issue | Produced by |
|---|---|---|
| `partner-preflight.json` | #330 | `python pilot/partner_preflight.py --write` |
| `archicad-dry-run-105.json` | #105 | same run |
| `archicad-audit-115.json` | #115 | same run |
| `product-walkthrough-312.json` | #312 | `python pilot/partner_walkthrough.py --write` |
| `friction-triage-331.json` | #331 | `python pilot/partner_triage.py --write` |

## What the evidence does and does not claim

It claims the loop is **correct and repeatable**: the bridge answers with the
official Graphisoft commands, the selection is read in `mode=live` with no fixture
fallback, the dry-run `before` value comes from the selected element, the model is
re-read afterwards and is unchanged, the audit separates present from missing
properties and ignores non-space elements, and the shareable transcript survives a
redaction check.

It does not claim an architect judged the result useful. That is business judgement,
not an invariant, and it is recorded as such wherever a partner opinion would apply.

## Pointing the same commands at a real seat

Nothing in the rig is replay-specific. With Archicad open and its JSON interface
enabled:

```bash
python pilot/partner_preflight.py --endpoint http://127.0.0.1:19723 --write
```

The checks, the invariants and the evidence shape are identical; only
`endpoint_kind` changes from `replay_stand_in` to `live_seat`.
